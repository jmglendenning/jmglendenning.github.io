b. Compare

Choose two to compare. For each, be ready to say: what does it assume the page looks like, what does it do about JavaScript, and what does it do about rate limiting?

Question rvest RSelenium
What does it assume the page looks like? Assumes the desired content is available in the returned HTML, where it can be selected using CSS selectors or XPath. Treats the site as a browser-rendered page and interacts with it much like a user would.
What does it do about JavaScript? Does not execute JavaScript. Content generated only after JavaScript runs generally will not be available to rvest alone. Uses a real browser/WebDriver, so JavaScript executes. It can scrape dynamically generated content and interact with buttons, forms, scrolling, etc.
What does it do about rate limiting? Nothing automatically. You need to control request frequency yourself, for example with delays or by combining it with polite. Nothing specifically for rate limiting. Browser interaction is naturally slower than simple HTTP requests, but request frequency still needs to be deliberately controlled.

c. robots.txt

What is robots.txt? Who writes it, who reads it, and what happens if you ignore it?

robots.txt is a small text file that a website can place at the root of its domain. It tells automated programs, especially web crawlers and scrapers, which parts of the site the site owner would prefer them to access or avoid. The site administrator writes it, but can be autogenerated. Crawlers, bots, etc. read it. It is not an access control mechanism, so it can be ignored easily.

If you ignore it, several things can happen:

  • The site may detect your scraper and throttle or block your IP address.
  • You may get 403, 429 Too Many Requests, CAPTCHAs, or other anti-bot responses.
  • Your behavior may violate the site’s Terms of Service.
  • You may impose an unwanted load on the website.
  • In some circumstances, there could be legal issues.

d. Find two

Find two websites’ robots.txt and analyse them. Append /robots.txt to any domain. For each file, identify:

i. the User-agent blocks — does the site treat all crawlers alike?

ii. what is Disallowed, and what is explicitly Allowed

iii. any Crawl-delay and any Sitemap

iv. whether the scrape you have in mind would be permitted

Check it from R, not by eye. The robotstxt package reads the file for you: robotstxt::paths_allowed("https://example.com/some/page"). The polite package wraps that check together with rate limiting, so compliance is the default rather than an afterthought.

Bring the two robots.txt files and your two-package comparison — we open class by arguing about whether permission and legality are the same thing.

  • Disallowed:

  • Disallowed: /

  1. Crawl-delay and Sitemap Crawl-delay:
  • dotbot: 10 seconds
  • AhrefsBot: 10 seconds
  • No crawl delay is specified for other crawlers. Sitemap:
  • https://www.spatialthinking.institute/sitemap.xml
  1. Would the scrape you have in mind be permitted? For a normal custom scraper using rvest or RSelenium, it appears generally permitted because:
  • the default User-agent: * block explicitly allows /
  • only URLs containing ?lightbox= are excluded
  • your scraper would not normally identify itself as PetalBot, dotbot, AhrefsBot, or Google AdsBot So the main restriction for your scraper would be:
  • do not scrape URLs containing ?lightbox=
  • still use reasonable request delays even though no general Crawl-delay is specified
  • separately check the site’s Terms of Service if the scraping is substantial or automated at scale The overall robots.txt policy is therefore quite permissive for an ordinary scraper.
