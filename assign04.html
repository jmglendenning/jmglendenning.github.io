The sources differ in both reporting vintage and, potentially, measurement or reporting conventions. Because the Wikipedia table contains country-specific reporting dates while the World Bank comparison holds the year at 2024, the values are not directly comparable as measurements from the same period. Extreme discrepancies should therefore be investigated individually before being interpreted as substantive changes in reserves.

c.

In two sentences: when is scraping the right tool?

Scraping is the right tool when the data are publicly available on a webpage but there is no structured way to access it. When an API or structured dataset is available, use that because it is reproducible, and less dependent on changes to the webpage’s HTML structure.

Wikipedia is a poor scraping target, and that is the lesson. It is volunteer-edited, has no schema, no versioning and no stated uncertainty, and the table shape changes without notice — so your parser breaks silently. It also has a documented API and bulk dumps, which means scraping it is a choice you did not have to make. Scrape when there is no other way in.

4. Data plan

Write one page: a plan to acquire web data for your own research.

a.

The primary source will be Media Cloud, using its online news archive to identify news articles related to data centers. Media Cloud is appropriate because it is designed specifically for media research and provides a large, searchable collection of online news sources. We will constrain our searches of this database by keywords and dates. This will create the URLs that we will scrape for our corpus. The list of publisher URLS will then be queried for text data. Media Cloud itself does not make its extracted article text available for download because of copyright restrictions.

b.

What robots.txt and the Terms of Service permit

We are not scraping Media Cloud, but its Terms of Use permit lawful use of the platform and specifically describe it as intended for academic, nonprofit, and journalistic research. The terms prohibit unreasonable bandwidth use and exceeding API request limits. They also distinguish Media Cloud’s own service from the third-party news content indexed by the service and thus Media Cloud does not grant permission to reproduce the underlying articles.

c.

Whether an API exists — and your justification if you scrape anyway

Media Cloud provides a search API, but we will generate a CSV so that we can preprocess the URL dataset.

Scraping is still necessary for the next stage because Media Cloud does not provide downloadable full article text. Where permitted, the URLs returned by the API will therefore be used to retrieve the original publisher pages and extract their article text.

d.

Volume, rate limiting, and how you will cache

Collection will be incremental rather than downloading the entire corpus at once. Our collection program will be respectful and implement delays and retries rather than repeatedly issuing requests after errors.

Successfully collected records will be cached locally and written to Parquet. Each record will contain the article text together with identifying and provenance fields such as source, source ID, URL, title, author when available, publication date, collection date, language, search query, and collection method. Before requesting an article again, the program will check whether it has already been successfully collected. This allows the program to be rerun without repeatedly downloading the same material.

e.

What breaks when the page changes, and how you will notice?

Scraping article text from publishers is always error prone because HTML structure differs among publishers and will change over time. A selector that identifies article text today may stop finding it after a site redesign, or it may begin capturing navigation, advertising, or other material instead.

The collection process will retain collection-status information and validate scraped results before treating them as successful. Missing text, unusually short text, HTTP errors, unexpected content, or changes in expected fields will be recorded as collection failures rather than cached as valid articles. Primary collection is via rvest, but on a failure, we also have implemented an Rselenium backup process. Because successful articles are already stored in the Parquet database, a change to a publisher’s website should require recollecting only failed or new records rather than rebuilding the entire corpus.
