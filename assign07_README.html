assign07.qmd

EPPS 6302 Assignment 7, “Social media data from the YouTube API,” revised to the updated assignment sheet (epps6302_assignment07.pdf). It collects YouTube videos and comments about the 2026 US midterm elections, before and after Election Day (3 November 2026), from three channels (NBC News, Fox News, BBC News). It then analyzes the comments with quanteda by channel and period, and compares them with the Assignment 6 corpora.

How the file is laid out

  • Every item on the assignment sheet appears in a quote block, word for word, with the sheet’s code formatting, bold and italics. The code and notes under each quote are the work.
  • Sub-items (i, ii, iii …) sit directly above the code that answers them.
  • The sheet’s two boxed notes (“The data expire.” and “Every comment section has a data-generating process.”) are callouts at the same places as on the sheet.
  • Headings follow the sheet: 0 Set up, 1 Read, 2 Collect, 3 Analyze, 4 Submit. Report and Data note are under 4 Submit.
  • Title and subtitle are the sheet’s, with “Instructor: Karl Ho” under them.

Rendering

  • The YAML sets execute: eval: false, so quarto render never calls the API.
  • Chunks marked Result (eval: true) run at render time. They read only files in results/assign07/: logs, manifests, aggregate tables and PNG plots. If a file is missing, the table shows “Not yet run” and inline values show “[not yet run]”.
  • Render from the folder that contains results/assign07/.
  • Run the collection and analysis chunks interactively in RStudio. Run 2e (after Election Day) in a fresh R session, after setup, parameters and the function chunks, so that yt_get_quota_usage() counts that period only.

Requirements

  • YOUTUBE_KEY in ~/.Renviron.
  • R packages: tuber 2.0.0.9000+ and httr2 ≥ 1.1.0 via pak::pak(c("soodoku/tuber", "httr2")); tidyverse, quanteda, quanteda.textstats, quanteda.textplots, jsonlite, usethis.
  • Optional (3c): vosonSML, igraph.

What changed in this revision

  • Assignment text. All item text replaced with the sheet’s exact wording, including the “What you will produce” paragraph, the reading list (the Freelon entry as the sheet gives it) and the two boxed notes. Paraphrased lead-ins under the items were rewritten so they no longer restate the sheet.
  • 3a.i (replies). The sheet now lists replies among the places the reported–received gap can go. A new chunk counts top-level comments and replies per video, and the Result table shows the split next to reported and received. The old combined Result chunk is split into 3a.i and 3a.ii.
  • “The data expire.” The sheet asks for a report reproducible from the code and the manifest, not from a saved copy. A new subsection, Rebuilding the comments from a manifest, adds rebuild_from_manifest(): it reads a published manifest and log and collects the same videos’ comments again (a new 30-day clock).
  • Policy section. Retention cites III.E.4.d (manifest text and data note).
  • 0b. The renamed-functions note lists the three functions the sheet names.
  • 2c/2e. route_summary() now has its own chunk (route-summary-fn), so 2e runs in a fresh session; 2e names the function chunks to run first.
  • tuber 3.0.0. pak installed tuber 3.0.0 (needs httr2 1.2.0 or later); the install check, the 0b note and the tuber reference now say so. collect_comments() logs an empty comment section as none even if tuber stops signalling it with a warning.
  • Replies without a video (tuber 3.0.0). 257 replies came back with no video_id, so they had no channel or period. load-comments now takes these from each reply’s parent comment, and collect_comments() writes the video ID onto every comment it collects.
  • Report. Written from the rendered results (about 670 words). Four bracketed spots remain: the kwic tally, your two phrases, keyness, and the hand-coding agreement. Each needs either your coding or the keyness tables.
  • Data note. The title-filter pattern now prints as code, so its backslashes survive.
  • 4b, posting. The YAML’s resources: copies every CSV and JSON in results/assign07/ to the site; the data note links the logs and manifests. A new publish-check chunk stops if the key, or a comment-text or commenter column, is in any of those files.
  • Section 4 is now “Submit”, with the sheet’s a and b quoted, then Report and Data note.
  • The section-map table at the top was removed; the table of contents covers it.
  • References are in alphabetical order (APA).

Before rendering

  • Existing manifests keep the old retention text (“III.E.4”); only new manifests carry “III.E.4.d”. Nothing else in them changes.

Checks done

  • 56 chunks, fences balanced, labels unique, all callout blocks closed.
