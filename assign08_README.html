assign08.qmd

EPPS 6302 Assignment 8, “Record Linkage” (epps6302_assignment08.pdf). It links two simulated administrative files, TRS (Teacher Retirement System) and TEA (Texas Education Agency), with the workshop’s deterministic rules and a probabilistic score. It then changes the corruption rate, the answer key, the blocking and the weights; calibrates a threshold and a REVIEW band; diagnoses errors; and ends with an ~800-word report and a data note.

How the file is laid out

  • Every item on the assignment sheet appears in a quote block, word for word, with the sheet’s code formatting, bold and italics. The code and notes under each quote are the work.
  • Sub-items (i, ii, …) sit directly above the code that answers them.
  • The sheet’s five boxed notes (“Why the answer key matters.”, “Blocking trades speed for recall.”, “A threshold is a policy, not a fact.”, “What a linked file claims.”, “Academic integrity.”) are callouts at the same places as on the sheet.
  • Headings follow the sheet: 0 Set up, 1 Read, 2 Build, 3 Calibrate, 4 Analyze, 5 Report, 6 Submit. The data note is under 6 Submit.
  • Title and subtitle are the sheet’s, with “Instructor: Karl Ho” under them. References (APA) and the AI-use disclosure are at the end.

Rendering

  • The YAML sets execute: eval: true. Every chunk runs at render time; the simulation and all analyses take a few seconds. _quarto.yml has freeze: auto, so the site re-runs it only when the file changes.
  • The page source()s the instructor’s record_linkage_workshop.R into its own environment (ws). It looks for the script next to the QMD first, then in ../Workshop/ (the course folder layout: EPPS6302/website/ and EPPS6302/Workshop/).
  • Every number in the prose is an inline R value, so text and tables cannot disagree.
  • Four stopifnot() checks stop the render if something drifts: make_data(0.20) must reproduce the workshop’s TRS, TEA and answer key exactly; score_pairs() must reproduce the workshop’s match_score for every pair; and no score may sit exactly on 0.95 (so >= and the script’s > agree).
  • No generated record is printed: names are masked to their first letter, birth dates cut to the year, and error tables show record IDs and similarities only (sheet item 6c).

Requirements

  • R packages: tidyverse, stringdist, phonics, data.table, logger (the workshop’s list; the script installs any that are missing), plus knitr.
  • record_linkage_workshop.R in the website folder or in ../Workshop/.

Choices made (change them if you disagree)

  • File name. assign08.qmd, following assign02–assign07. The sheet asks for assign_linkage.qmd; rename if you want to match it exactly.
  • Priority: precision. A false link would attach one teacher’s pension record to another’s certification record; a missed link only lowers a count. A false link is counted as 10× a missed one. This sets the threshold at 0.95 and the REVIEW band at 0.90 to just below 0.95.
  • Weights. log(m/u) per field, divided by their sum so the score stays on the workshop’s 0–1 scale: 0.175 / 0.180 / 0.644 (last / first / date of birth).
  • Blocking. The sheet’s first-letter rule drops 3 true matches at 40% corruption, so the chosen method uses a union: same first letter of last name or same birth year (no true match lost, ~86% fewer pairs).
  • 4d (optional) is included: a hand-written EM on the eight agreement patterns.

Results at a glance (20% corruption unless noted)

  • Workshop as distributed: 80 / 9 / 4 rule links + 4 probabilistic; precision 1.000, recall 0.970. Its printed “accuracy” equals recall because the assessment table has no true negatives.
  • 2a: recall falls 0.99 → 0.97 → 0.93 at corruption 0.10 / 0.20 / 0.40; precision stays 1.000. Every miss is a last-name typo.
  • 2b: dropping slice(1:100) moves the curve by 0 — the validation set has exactly 100 rows. The real distortion is that the original curve ignores the rules’ 93 links (recall capped at 0.07).
  • 2c: first-letter blocking cuts 165,649 pairs to 19,030; 0 true matches lost at 20%, 3 at 40%.
  • 2d/3: with m/u weights, precision = recall = 1 for every threshold from 0.91 to 0.97, at all three corruption rates.
  • 4a: no errors at the chosen threshold, so the page lists the 10 + 10 near misses and counts the errors that occur under other settings.
  • 4d: EM weights match the key-based ones to within 0.003, but EM estimates 149 matches instead of 100.

Checks done

  • Rendered with Quarto 1.6.42 and R 4.3.3: all 32 chunks ran, the four stopifnot() checks passed, and the threshold-curve figure was inspected.
  • The quoted text and the five boxes were compared with the PDF word for word. The only difference: “Regenerate” (2a) breaks across a line in the PDF as “Re-/generate”; the QMD uses “Regenerate”.
  • 32 chunks, labels unique, fences balanced, all callout blocks closed.
  • The report (section 5) is about 820 words including the table caption.
  • The sheet says the probabilistic step compares 499 × 499 pairs; the script as distributed leaves 407 × 407. The page reports the script’s numbers and notes the difference in 0a.
  • The workshop script’s results were reproduced on Linux; R’s random number generator is the same across platforms, so a Mac render should give the same numbers.
